# 判定

用語は [CONTEXT.md](../CONTEXT.md)。画面への出し方は [design.md](./design.md)。モデルの起動は [ollama.md](./ollama.md)。

## 結論

`適切 = 意味が原文と合う ∧ 文法が破綻していない`。

自然さとトーンは結論に入れない。適切なら [指摘](../CONTEXT.md) を出してよい。不適切なら [ヒント](../CONTEXT.md) と [箇所](../CONTEXT.md) を対で出し、訳文の全文も、より良い訳も出さない。誤りごとにヒントの短文と箇所の要素を1対1で対応させる。片方だけの出力はしない。

ニュース記事でも自分の作文でも、判定は同じである。

## 箇所

不適切のときだけ訳文上に出す。適切なら空にする。今回の表示は、適切でない単語（連続した文字列）への赤い波線だけである。

位置は訳文の Unicode スカラー値（文字）の 0 始まり。半開区間 `[start, end)` で、`0 ≤ start < end ≤ 文字数`。範囲外や逆転は捨てる。正しい訳や補うべき語そのものは出さない。

## 言語共通

英語も次の型に合わせる。

| 結果           | 条件                                                                     |
| -------------- | ------------------------------------------------------------------------ |
| 不適切（意味） | 訳文が原文と別のことを言っている。主語・否定・時制・数量の取り違えを含む |
| 不適切（文法） | 述語がない、一致が壊れている、語順が通らない                             |
| 指摘           | 意味も文法も足りるが、不自然、またはトーンが原文とずれる                 |
| 見ない         | 米語／英語の綴り差だけ。指摘にもしない                                   |

ヒントは母語（日本語）。各誤りを短く指す。「単語が違います」「動詞がありません」のように、欠けや誤りを指す。正しい訳を例示しない。誤りが複数なら、ヒントは箇所と同じ順・同じ個数の短文を「 / 」でつなぐ。

指摘も母語で、一文以内。より自然な言い方を示してよいが、全文の書き直しにはしない。

## 中国語（簡体）

字体は簡体だけ。繁体で書かれていても、字体の違いは見ない（不適切にも指摘にもしない）。別の意味になっていれば意味の不適切。

| 現象                | 扱い           |
| ------------------- | -------------- |
| 動詞がない          | 不適切（文法） |
| 語順が通らない      | 不適切（文法） |
| 了 / 着 / 过 の誤り | 指摘           |
| 量詞の誤り          | 指摘           |
| 通じるが不自然      | 指摘           |

## 韓国語

| 現象                          | 扱い           |
| ----------------------------- | -------------- |
| 述語がない                    | 不適切（文法） |
| 活用が壊れている              | 不適切（文法） |
| 助詞の取り違え（を／が など） | 不適切（文法） |
| 은/는 と 이/가 の揺れ         | 指摘           |
| 敬語のずれ                    | 指摘（トーン） |

## ドイツ語

| 現象               | 扱い           |
| ------------------ | -------------- |
| 格が違う           | 不適切（文法） |
| 人称変化が違う     | 不適切（文法） |
| 動詞第二位が崩れる | 不適切（文法） |
| 性・冠詞が違う     | 不適切（文法） |
| 通るが不自然       | 指摘           |

## LLM に渡すもの

判定対象は今の [文](../CONTEXT.md) だけである。材料には [原文](../CONTEXT.md) 全体を付ける。代名詞と省略を、原文の他の文と矛盾させないため。

```text
学習言語: {英語|中国語（簡体）|韓国語|ドイツ語}
原文:
{全文}

対象の文:

```

訳文が空なら LLM を呼ばない。

## 応答の形

Rust 側は JSON 以外を捨ててやり直す（最大1回）。フィールドは次に固定する。

```json
{
  "tekisetsu": true,
  "imi": true,
  "bunpo": true,
  "shiteki": null,
  "hinto": null,
  "kasho": []
}
```

| フィールド  | 型             | 規則                                                                                                     |
| ----------- | -------------- | -------------------------------------------------------------------------------------------------------- |
| `tekisetsu` | bool           | `imi && bunpo` と一致させる。ずれて来たら `imi && bunpo` を採用する                                      |
| `imi`       | bool           | 意味が原文と合うか                                                                                       |
| `bunpo`     | bool           | 文法が破綻していないか                                                                                   |
| `shiteki`   | string \| null | `tekisetsu` が true のときだけ文字列可。false なら null                                                  |
| `hinto`     | string \| null | `tekisetsu` が false のとき必須。true なら null。訳文全体を含めてはならない。短文の個数は `kasho` と一致 |
| `kasho`     | array          | `tekisetsu` が false のとき必須（1件以上）。true なら `[]`。各要素は下表。`hinto` の短文と1対1           |

`kasho` の要素:

```json
{ "shurui": "ayamari", "start": 0, "end": 4 }
```

| `shurui`  | フィールド               | 規則                             |
| --------- | ------------------------ | -------------------------------- |
| `ayamari` | `start` / `end` (number) | `0 ≤ start < end ≤ 訳文の文字数` |

プロンプト本文は `apps/app` の Rust に置く。学習言語ごとの破綻表を、その言語のときだけプロンプトに足す。模範解答を求めない。
